1. SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------

OVERVIEW
  SwarmNet v2.0 is a three-container Docker system running on macOS M4 Pro.
  QGroundControl runs natively on macOS outside Docker. All containers
  share a Docker bridge network (swarm_net) and communicate via DDS (RTPS).

CONTAINER MAP

  +---------------------+     +----------------------+     +--------------+
  |   Container 1       |     |   Container 2        |     |  Container 3 |
  |   px4_sitl          |     |   ros2_nodes         |     |  ai_trainer  |
  |                     |     |                      |     |              |
  |  50x PX4 SITL       |<--->|  Master node         |     |  MAPPO train |
  |  Gazebo Harmonic    | DDS |  49x Follower nodes  |<--->|  PyTorch MPS |
  |  Wind plugin        |     |  ORCA nodes          |     |  Actor/Critic|
  |  Physics sim        |     |  EKF nodes           |     |  Gym env     |
  |                     |     |  MPC nodes           |     |              |
  +---------------------+     |  PBFT module         |     +--------------+
           |                  |  Metrics collector   |
           | UDP 14550        +----------------------+
           |                           |
  +---------------------+     +--------+-------+
  |  QGroundControl     |     |   RViz2        |
  |  (macOS native)     |     |   (in VS Code  |
  |  Operator GCS       |     |    Remote Cont)|
  +---------------------+     +----------------+

DRONE ROLE ARCHITECTURE

  Vehicle 1 (MASTER)
    Responsibilities:
    - Receives mission from QGroundControl via MAVLink
    - Runs Hungarian algorithm to assign formation positions
    - Hosts MAPPO centralized critic (training only)
    - Publishes /swarm/formation_targets DDS topic
    - Maintains Raft leader role
    - Monitors follower health via /swarm/drone_state topics
    - Triggers re-assignment on follower failure

  Vehicles 2–50 (FOLLOWERS)
    Each runs independently:
    - Subscribes to /swarm/formation_targets
    - Runs EKF: fuses IMU + baro + optical flow → position estimate
    - Runs MPC: position estimate → thrust setpoint
    - Runs ORCA: thrust setpoint → collision-safe velocity
    - Runs MAPPO actor: local obs → policy action (overrides MPC)
    - Publishes /swarm/drone_state/<id> at 10 Hz
    - Holds last formation position for 10s on comms loss

5.1 EKF SENSOR FUSION
----------------------

PURPOSE
  Estimate true drone position in 3D space by fusing multiple noisy
  sensors. Critical for maintaining 50cm spacing when GPS is degraded.

STATE VECTOR (15-dimensional)
  x = [px, py, pz,          # position (m)
       vx, vy, vz,          # velocity (m/s)
       roll, pitch, yaw,    # attitude (rad)
       bx, by, bz,          # accelerometer bias (m/s²)
       balt]                # barometer bias (m)

SENSOR MODELS
  IMU (1000 Hz):
    z_imu = R(q) * (a_true - g) + b_acc + noise_imu
    Noise: sigma_acc = 0.005 m/s², sigma_gyro = 0.001 rad/s

  Barometer (50 Hz):
    z_baro = pz + b_alt + noise_baro
    Noise: sigma_baro = 0.1 m

  Optical Flow (30 Hz):
    z_flow = [vx, vy] + noise_flow (valid up to 10m/s wind)
    Noise: sigma_flow = 0.02 m/s

  GPS (10 Hz, degraded under jamming):
    z_gps = [px, py, pz] + spoof_offset + noise_gps
    Noise: sigma_gps = 0.5 m (nominal), 10 m (spoofed)
    When RSSI drops below threshold: GPS weight → 0 (rejected)

EKF CYCLE (every 1ms, fuse available sensor when ready)
  PREDICT:   x_k = f(x_{k-1}, u_k)      // quadrotor dynamics
             P_k = F * P_{k-1} * F^T + Q // propagate covariance
  UPDATE:    K = P_k * H^T * (H*P_k*H^T + R)^{-1}  // Kalman gain
             x_k = x_k + K * (z - H * x_k)
             P_k = (I - K*H) * P_k

IMPLEMENTATION
  C++ ROS2 node: ekf_node.cpp
  Uses Eigen3 for matrix operations
  Publishes: /drone_{id}/ekf/state  at 100 Hz (PoseWithCovarianceStamped)


5.2 MPC POSITION CONTROLLER
-----------------------------

PURPOSE
  Compute optimal thrust sequence that drives drone to formation target
  while pre-compensating for wind disturbance.

SYSTEM MODEL (discrete, dt = 50ms)
  x_{k+1} = A * x_k + B * u_k + w_k
  where:
    x_k = [px, py, pz, vx, vy, vz]   state
    u_k = [Fx, Fy, Fz]                thrust forces
    w_k = wind disturbance (estimated from EKF)
    A, B = linearized quadrotor dynamics matrices

OPTIMIZATION PROBLEM (solved every 50ms)
  minimize   sum_{k=0}^{N-1} [ (x_k - x_ref)^T Q (x_k - x_ref)
                               + u_k^T R u_k ]
             + (x_N - x_ref)^T P (x_N - x_ref)

  subject to:
    x_{k+1} = A*x_k + B*u_k + w_k
    |u_k| <= U_MAX  (thrust limits)
    |x_k - x_ref| >= 0.5m  (ORCA spacing — soft constraint here)

  Parameters:
    N = 10 (horizon steps, 500ms at dt=50ms)
    Q = diag(10, 10, 10, 1, 1, 1)    position error weight
    R = diag(0.1, 0.1, 0.1)           control effort weight
    U_MAX = 15 N per axis

SOLVER
  OSQP (C++ library) — fast QP solver, solves in < 10ms for N=10
  ROS2 node: mpc_node.cpp
  Publishes: /drone_{id}/mpc/thrust_setpoint at 20 Hz


5.3 ORCA COLLISION AVOIDANCE
------------------------------

PURPOSE
  Post-process MPC velocity commands to guarantee minimum 50cm spacing.
  Each drone independently computes a collision-free velocity.

INPUTS PER DRONE (every 20ms)
  - Own position (px, py, pz) from EKF
  - Own velocity (vx, vy, vz) from EKF
  - Positions and velocities of K nearest drones from DDS state topic
    (K = 10 nearest, found via K-D tree on gossip state)

VELOCITY OBSTACLE (VO) CONSTRUCTION
  For each neighbor j:
    VO_ij = { v | exists t in [0, tau]: p_ij + t*(v - v_j) in D(r_ij) }
    where:
      p_ij = p_i - p_j            relative position
      r_ij = 0.5m                 sum of safety radii (0.25m each)
      tau = 1.0s                  time horizon
      D(r) = disk of radius r     collision region

  ORCA half-plane:
    ORCA_ij = { v | (v - (v_pref + u/2)) . n >= 0 }
    where u = closest point on boundary of VO to v_pref

LINEAR PROGRAM
  Find v_new that:
    - Satisfies all ORCA_ij half-planes (one per neighbor)
    - Minimizes |v_new - v_mpc|  (stay close to MPC command)
  Solved via LP in O(K) time (< 2ms for K=10)

EMERGENCY STOP
  If any neighbor within 0.3m: publish EMERGENCY_HOVER immediately.
  Overrides all other commands.

IMPLEMENTATION
  C++ ROS2 node: orca_node.cpp
  Uses libRVO2-3D (3D extension of RVO2 library)
  Publishes: /drone_{id}/orca/velocity_cmd at 50 Hz


5.4 MAPPO AI SWARM CONTROLLER
-------------------------------

PURPOSE
  Replace hand-tuned MPC weights with a learned control policy that
  generalizes across weather, jamming, and dynamic formation changes.

ARCHITECTURE
  Centralized Training / Decentralized Execution (CTDE):
    Training:  Master runs centralized critic (sees all 50 drones)
    Inference: Each follower runs own actor (sees local observation only)

OBSERVATION SPACE (per drone, 47-dimensional)
  own_pos:          [px, py, pz]                          3
  own_vel:          [vx, vy, vz]                          3
  own_target_delta: [dx, dy, dz] to formation target      3
  neighbor_rel_pos: [dx,dy,dz] × 10 nearest drones       30
  neighbor_rel_vel: [dvx,dvy,dvz] × 10 nearest           (compressed 3)
  wind_estimate:    [wx, wy, wz]                          3
  battery:          [b]                                   1
  raft_state:       [0=follower, 1=leader]                1
  Total:                                                  47

ACTION SPACE (per drone, 4-dimensional, continuous)
  [delta_thrust_x, delta_thrust_y, delta_thrust_z, delta_yaw_rate]
  Range: [-1, 1] normalized, scaled by MAX_THRUST at execution

REWARD FUNCTION (per step, per drone)
  R = w1 * formation_reward
    + w2 * collision_penalty
    + w3 * energy_penalty
    + w4 * task_completion_bonus

  formation_reward  = -||pos_i - target_i||^2 / scale
  collision_penalty = -1000  if dist(i,j) < 0.5m for any j
                    = 0      otherwise
  energy_penalty    = -||action||^2 * 0.01
  task_completion   = +100   if all drones within 5cm of target

  Weights: w1=1.0, w2=5.0, w3=0.1, w4=2.0

ACTOR NETWORK (per drone)
  Input:  47-dim observation vector
  Layer1: Linear(47 → 128) + LayerNorm + Tanh
  Layer2: Linear(128 → 128) + LayerNorm + Tanh
  Layer3: Linear(128 → 64) + Tanh
  Output: Linear(64 → 4) + Tanh  → action mean
          Linear(64 → 4) + Softplus → action std (for stochastic policy)
  Total parameters: ~35,000

CRITIC NETWORK (centralized, master only during training)
  Input:  47 * 50 = 2350-dim global state vector
  Layer1: Linear(2350 → 512) + LayerNorm + ReLU
  Layer2: Linear(512 → 256) + ReLU
  Layer3: Linear(256 → 128) + ReLU
  Output: Linear(128 → 1) → value estimate
  Total parameters: ~1.4M

MAPPO TRAINING LOOP
  1. Collect T=2000 steps from 50 drones in Gazebo (rollout buffer)
  2. Compute advantages using GAE (gamma=0.99, lambda=0.95)
  3. Update critic: minimize MSE(V(s), returns) for K=10 epochs
  4. Update actor: maximize clipped PPO objective, clip=0.2
  5. Entropy bonus: 0.01 * H(pi) to encourage exploration
  6. Repeat for 10,000+ episodes
  7. Save best actor weights to /models/mappo_actor.pt

APPLE MPS TRAINING
  device = torch.device("mps")  # M4 Pro GPU
  All tensors and networks moved to MPS device
  Expected training speed: ~3x faster than CPU on M4 Pro

INFERENCE DEPLOYMENT
  Load: actor.load_state_dict(torch.load('/models/mappo_actor.pt'))
  Run on CPU in follower ROS2 node (MPS not available in Docker CPU mode)
  Latency: < 5ms per inference on M4 Pro CPU (35K param network)
  Fallback: if inference > 40ms → use MPC output instead


5.5 FHSS JAMMING DEFENSE
--------------------------

PURPOSE
  Simulate frequency-hopping spread spectrum to maintain comms under
  RF jamming. Detect jamming early via RSSI monitoring.

RSSI MONITORING
  Each drone monitors simulated signal strength of DDS heartbeats.
  RSSI modeled as: RSSI = RSSI_nominal - jammer_power * distance_factor
  Jam detection threshold: RSSI < -85 dBm

FHSS SIMULATION
  15 virtual channels defined (ports 7400–7414 in Cyclone DDS config)
  Hopping sequence: pseudo-random, seeded with shared swarm key
  Hop rate: every 100ms under normal operation
  Forced hop: immediately on jam detection
  Channel unavailable: simulated by dropping all DDS messages on port

JAMMING INJECTION (test mode)
  JammerNode publishes /swarm/jammer topic with:
    intensity:  0.0 – 1.0  (fraction of messages dropped)
    spoof_gps:  True/False  (activates GPS spoof offset)
    spoof_mag:  0 – 10 m   (GPS offset magnitude)

GPS SPOOFING RESPONSE
  EKF detects spoofing: GPS innovation > 3σ threshold → reject GPS
  Fallback: optical flow + IMU dead reckoning
  Alert: publish /swarm/alerts/gps_spoofed (triggers PBFT lockdown)


5.6 PBFT BYZANTINE CONSENSUS
------------------------------

PURPOSE
  Ensure critical swarm commands (formation change, abort, emergency land)
  cannot be executed by a compromised or malfunctioning drone.

PARAMETERS
  N = 50 drones total
  f = floor(50/3) = 16 maximum Byzantine faults tolerated
  Quorum = 2f+1 = 33 drones must agree for command to execute

THREE-PHASE PROTOCOL (per critical command)

  PHASE 1 — PRE-PREPARE (Master → All)
    Message: {type: PRE_PREPARE, view: v, seq: n, cmd: C, digest: H(C)}
    Master signs with its private key (simulated HMAC)

  PHASE 2 — PREPARE (All → All)
    On valid pre-prepare: each honest drone broadcasts:
    Message: {type: PREPARE, view: v, seq: n, digest: H(C), drone_id: i}
    Drone proceeds to commit phase after receiving 2f PREPARE messages
    matching the same (view, seq, digest)

  PHASE 3 — COMMIT (All → All)
    Message: {type: COMMIT, view: v, seq: n, digest: H(C), drone_id: i}
    Drone executes command after receiving 2f+1 COMMIT messages

  VIEW CHANGE (on primary failure)
    Drone suspects primary if no pre-prepare in 2s (timeout)
    Broadcasts: {type: VIEW_CHANGE, new_view: v+1, drone_id: i}
    New primary = argmin(drone_id) of alive drones (deterministic)
    New primary starts after 2f+1 VIEW_CHANGE messages received

MESSAGE COMPLEXITY
  Pre-prepare: O(N)    (1 master → N drones)
  Prepare:     O(N²)   (N drones → N drones)
  Commit:      O(N²)   (N drones → N drones)
  Total per command: O(N²) = ~2500 messages for N=50

PBFT SCOPE (what it protects)
  Protected commands:    CHANGE_FORMATION, EMERGENCY_LAND, ABORT_MISSION,
                         RETURN_TO_HOME, SWARM_HALT
  Not protected:         Position updates, state gossip, heartbeats
                         (these are too frequent for PBFT overhead)

IMPLEMENTATION
  Python ROS2 node: pbft_node.py
  One instance per drone (master and followers)
  Subscribes: /swarm/pbft/incoming
  Publishes:  /swarm/pbft/outgoing


5.7 HUNGARIAN FORMATION ASSIGNMENT
-------------------------------------

PURPOSE
  Optimally assign N formation target positions to N drones to minimize
  total travel distance during formation transitions.

ALGORITHM
  Input:  N drone positions, N target positions
  Output: bijective assignment drone_i → target_j

  1. Build N×N cost matrix C where C[i][j] = ||drone_i - target_j||²
  2. Run Hungarian algorithm (Kuhn-Munkres): O(N³)
     With N=50: O(125,000) operations — completes in < 1ms
  3. Output assignment array: assignment[i] = j
  4. Publish /swarm/formation_targets with per-drone targets

LIBRARY
  scipy.optimize.linear_sum_assignment (Python, in master_node.py)
  Re-runs every time: formation changes, drone fails, drone recovers

FORMATION PRESETS
  V_FORMATION:     positions on two diagonal lines from master
  GRID_FORMATION:  7×7 grid with 2m spacing (50 positions)
  CIRCLE:          concentric rings (master center, 49 on rings)
  LINE:            single file, 2m spacing
  CUSTOM:          loaded from YAML file

6. COMMUNICATION ARCHITECTURE
--------------------------------------------------------------------------------

PROTOCOL STACK

  QGroundControl ←→ MAVLink v2 UDP ←→ MAVROS2 ←→ ROS2 topics
  PX4 firmware   ←→ uXRCE-DDS     ←→ ROS2 topics
  Drone ↔ Drone  ←→ Cyclone DDS   ←→ ROS2 topics (pub/sub)
  PBFT           ←→ Cyclone DDS   ←→ /swarm/pbft/* topics

ROS2 TOPIC DESIGN

  /swarm/formation_targets         (master publishes, all drones subscribe)
    Type: swarmnet_msgs/FormationTargets
    Rate: on change (formation update)
    Content: array of 50 PoseStamped targets with drone_id assignment

  /swarm/drone_state/<drone_id>    (each drone publishes)
    Type: swarmnet_msgs/DroneState
    Rate: 10 Hz
    Content: position, velocity, battery, raft_state, task, alive

  /drone_<id>/ekf/state            (EKF node publishes)
    Type: geometry_msgs/PoseWithCovarianceStamped
    Rate: 100 Hz

  /drone_<id>/mpc/thrust_setpoint  (MPC node publishes)
    Type: geometry_msgs/Vector3Stamped
    Rate: 20 Hz

  /drone_<id>/orca/velocity_cmd    (ORCA node publishes)
    Type: geometry_msgs/TwistStamped
    Rate: 50 Hz

  /drone_<id>/px4/offboard_setpoint (sent to PX4 via uXRCE-DDS)
    Type: px4_msgs/TrajectorySetpoint
    Rate: 50 Hz (PX4 requires > 2 Hz in OFFBOARD mode)

  /swarm/jammer                    (test node publishes for benchmarks)
    Type: swarmnet_msgs/JammerState
    Rate: on change

  /swarm/alerts/<type>             (any drone publishes alerts)
    Type: std_msgs/String
    Rate: event-driven

  /swarm/pbft/incoming             (PBFT messages, all drones)

8. PX4 SITL CONFIGURATION
--------------------------------------------------------------------------------

SPAWN SCRIPT: drone_spawn.py

  Spawns 50 PX4 SITL instances with unique parameters:
    MAV_SYS_ID:    1–50 (unique vehicle ID)
    UDP port:      14550–14599 (MAVLink to QGC)
    DDS port:      incremented from base 8888
    Gazebo model:  x500_swarmnet (spawned at grid positions)
    Initial pos:   7×7 grid with 2m spacing, centered at origin

  Grid position formula:
    row = (drone_id - 1) // 7
    col = (drone_id - 1) % 7
    x_init = (col - 3) * 2.0    # meters
    y_init = (row - 3) * 2.0    # meters
    z_init = 5.0                  # meters altitude

PX4 PARAMETERS (per drone, set via MAVLink)
  SYS_VEHICLE_TYPE  = 1 (multicopter)
  COM_RCL_EXCEPT    = 4 (allow offboard without RC)
  NAV_RCL_ACT       = 0 (no RC loss action in sim)
  EKF2_AID_MASK     = 1 (GPS) → 24 (optical flow) under jamming
  MPC_XY_P          = 0.95 (position P gain, tuned for 50cm spacing)
  MPC_Z_P           = 1.0

PX4 FLIGHT MODES USED
  OFFBOARD:  primary mode. ROS2 sends TrajectorySetpoint at 50 Hz.
  HOLD:      fallback on comms loss (10s autonomous hold).
  LAND:      triggered by PBFT emergency command.
  RTL:       triggered by low battery (< 20%).

11. API & INTERFACE SPECIFICATIONS

QGC INTERFACE (MAVLink v2)
  Connection: UDP localhost:14550 (Vehicle 1 / Master)
  Secondary:  UDP localhost:14551–14599 (Vehicles 2–50)
  Streams:    HEARTBEAT, GLOBAL_POSITION_INT, ATTITUDE,
              BATTERY_STATUS, SYS_STATUS, GPS_RAW_INT

MASTER NODE ROS2 SERVICES
  /swarm/change_formation   (swarmnet_msgs/srv/ChangeFormation)
    Request:  formation_type (uint8), waypoint (PoseStamped)
    Response: success (bool), assignment (DroneTarget[])

  /swarm/emergency_land     (std_srvs/srv/Trigger)
    Triggers PBFT EMERGENCY_LAND command

  /swarm/get_status         (swarmnet_msgs/srv/GetSwarmStatus)
    Response: all DroneState[], leader_id, formation_error_rms

METRICS HTTP API (Flask, port 5001 inside ros2_nodes)
  GET  /metrics/current     → JSON: all KPIs at current timestep
  GET  /metrics/export      → CSV file download
  POST /jammer/set          → Body: {intensity, gps_spoof, magnitude}
  POST /formation/change    → Body: {type: "grid"|"V"|"circle"}
  POST /drone/kill/<id>     → Simulate drone failure

MAPPO TRAINING SCRIPT
  python3 mappo/train.py \
    --n-drones 50 \
    --episodes 10000 \
    --device mps \
    --save-path /workspace/models/mappo_actor.pt \

15. DEPLOYMENT & RUN INSTRUCTIONS
--------------------------------------------------------------------------------

PREREQUISITES (macOS M4 Pro)
  1. Docker Desktop (Apple Silicon) — 12GB RAM, 8 CPU allocated
  2. XQuartz — brew install --cask xquartz (restart Mac after)
  3. VS Code + Remote Containers extension
  4. QGroundControl — native macOS ARM64 build from qgroundcontrol.com

FIRST-TIME SETUP
  git clone https://github.com/yourusername/swarmnet_v2.git
  cd swarmnet_v2
  docker compose pull                   # Pull all images (~15GB total)

LAUNCH SIMULATION
  docker compose up -d                  # Start all containers
  docker exec -it swarmnet_px4 bash     # Enter PX4 container
  python3 /px4_config/scripts/drone_spawn.py --n 50

LAUNCH ROS2 NODES
  docker exec -it swarmnet_ros2 bash
  source /opt/ros/humble/setup.bash
  cd /ros2_ws
  colcon build --packages-select swarmnet_msgs swarmnet_master \
               swarmnet_follower swarmnet_comms swarmnet_metrics
  source install/setup.bash
  ros2 launch swarmnet_master master.launch.py n_drones:=50

CONNECT QGC
  Open QGroundControl on macOS
  Application Settings → Comm Links → Add UDP → Port 14550
  All 50 vehicles will appear on map

LAUNCH RVIZ2
  ros2 launch swarmnet_metrics rviz2.launch.py

TRAIN MAPPO
  docker exec -it swarmnet_ai bash
  cd /workspace/mappo
  python3 train.py --n-drones 10 --episodes 5000 --device mps
  # After training: weights saved to /workspace/models/mappo_actor.pt

RUN BENCHMARKS
  docker exec -it swarmnet_ros2 bash
  python3 -m swarmnet_metrics.plot_generator --benchmark all

RUN TESTS
  docker exec -it swarmnet_ros2 bash
  pytest /ros2_ws/tests/ -v --cov=swarmnet_ros2

STOP ALL CONTAINERS
  docker compose down

KILL ALL SITL PROCESSES (if stuck)
  docker exec swarmnet_px4 pkill -f px4
